# 电池货出货手续包生成器

数据链：**订舱邮件 → 提取要素 → chinasdg 鉴定匹配 → 七份手续生成**。

## 数据源（按权威性排序）

1. **订舱邮件 `.eml`**：唯一数据源。主单号格式 `176- 61333915`（横线后可能有空格，需归一化 `176-\s*(\d{8})`）。HAWB 表结构：`件数 计费 毛重 kg we cm HAWB 机种（按型号拉鉴定） 报关行 预报单号 主单号号 航班`，主单号只出现在该主单第一行（合并单元格）。文本流顺序 = `[件数 计费 毛重 尺寸] + [HAWB 机种 报关行 预报单号 主单号 航班]`。
2. **鉴定数据源 xlsx**：`templates/苹果手机-网站查询信息汇总.xlsx`（chinasdg 官网查询结果汇总，脚本默认指向它）：sheet「网站查询信息」，列含 `证书编号(报告编号)`/`物品名称`(中)/`Name of Goods`(英)。每机型两条（手机模组 + 数字式手机变体），**参考版手续用「数字式手机/5G数字移动电话机」变体**。
3. **运单副本 PDF 品名栏印字不是数据源**——它是要填的目标，绝不可反查。

## 流程

### 0. 一键入口（独立运行，不需 AI）
```
把 订舱邮件.eml 拖到 DSV 根目录「一键出货手续包.bat」上（= scripts/run_package.py）
```
- 闸门 G1-G6：表格/主单/HAWB 件重解析 → 目的站/航班/日期提取 → 机型⊆鉴定汇总 → 机型⊆CN_GOODS 且模板齐 → 生成后文本层校验。
- G2-G5 缺失：起 127.0.0.1 临时服务打开**补充页**（`serve_fill_form`）：目的站/航班/日期、分单件数/毛重/机型、机型证书编号/中英文品名直接在页面补，点「补充并重新校验」自动合并重跑闸门。
- 闸门全过 → **不直接生成**，先开「**生成前核对单**」（`serve_confirm`）等人工确认：展示各主单 HAWB/件重/机型/证书号/品名，**鉴定证书编号可直接在页面上改**（新编号在汇总里查得到→该机型的品名同步改用对应证书行；查不到→只改编号品名不变，见 `apply_cert_edits`/`cert_overrides`）。点「确认生成」才生成七份手续 + 正式核对单；点「取消」/Ctrl+C 不生成。
- 设 `RUNPKG_AUTO_CONFIRM=1` 跳过确认页直接生成（自动化/测试用）；`RUNPKG_NO_OPEN=1` 阻止自动打开页面/文件。
- G1（邮件格式解析不了）：页面补不了，出 `异常报告_*.html` 写明人工介入点。

### 0b. 服务器邮件守护模式（Linux 部署）
```
scripts/mail_daemon.py + scripts/mail_config.ini（照 mail_config.ini.template 填）
systemd 服务：server/dsv-mail.service；部署步骤：server/部署说明.md
```
- 流程：IMAP 轮询收件箱 UNSEEN → 剥出订舱邮件本体（内嵌 rfc822/.eml 附件/内联正文三种转发形态）→ 附件里「主单号+托书/运单副本」的 PDF 自动入 `测试2/{主单}模板/` → `run_headless` 探测闸门。
- 新主单模板也是发邮件给：随订舱邮件附件一起发（一步到位）或单独发纯模板邮件（回确认信）；纯模板邮件入库后 `retry_pending_jobs` 会把等该模板的待补充任务自动生成回信。
- 分支：闸门全过直接生成并回信 zip+核对单；缺信息回信**公网令牌补充页**（`/t/{token}/`，`build_form_html` 复用）补齐提交后自动生成回信；硬伤回信异常说明。缺模板类问题文案由 `server_issues` 改写为「把 PDF 作为邮件附件发到本邮箱」。
- **同主单重复转发=覆盖重生成**（应对后期更改）：旧版存档到 `出货手续包/_存档/{主单}_{时间}/`（`archive_existing`）。
- 待补充任务落盘 `出货手续包/_daemon_jobs.json`，重启不丢链接；已处理 UID 存 `_daemon_state.json` 防重复。
- 回信用 SMTP（`smtp_send`，In-Reply-To 串起会话）；结果邮件 HTML 内嵌正式核对单报告。

### 1. 解析订舱邮件
```
python scripts/booking_to_waybill.py 订舱邮件.eml [--xlsx templates/苹果手机-网站查询信息汇总.xlsx]
```
- 按 `件数 计费 毛重` 切表格区；**处理范围 = 第一个表格之前摘要里列出的主单**（转发「完整版」里的其他票不处理）。按 HAWB 切行（区域止于**下一个 HAWB**，报关行不一定是泽坤），取主单号（段内最后一个 `176-\s*\d{8}`，去空格归一化）+ 机型（`A\d{4}`）+ 件数/计费/毛重三元组（后接尺寸括号行作锚，**尺寸行行首允许空格**）。
- 新机型品名不用改代码：`inject_goods` 自动从 xlsx「数字式手机/5G数字移动电话机」变体补进 CN_GOODS/EN_GOODS；只有 xlsx 也没有该变体时才报 G5。
- 电池标记兼容「手机含电池」与「手机模组含电池」；机型直接取区域内全部 `A\d{4}`（无分号也兼容）。
- **转发邮件下方常带引用历史表格**：无主单号的块丢弃、重复分单以首次出现为准，否则旧版数据污染机型并集。
- `--full-package`：邮件进→手续包出。提取结果聚成 MASTERS（models=含电池分单机型并集、hawbs=全部分单(件数,毛重)、battery 从 CN_GOODS 反提），先与内置 MASTERS 交叉核对打印一致率，再调 gen_procedures 每主单生成七份。
- 电池机型归属示例（RUH 176-61333915：8 机型 A2636/A2881/A2889/A3089/A3101/A3286/A3295/A3408；176-61333926：7 机型 A2403/A2407/A3089/A3101/A3286/A3295/A3408）。

### 2. 匹配鉴定品名
- 机型 → xlsx「物品名称」按 `A\d{4}` 子串匹配 → 取**数字式手机/5G数字移动电话机**变体（中/英文，含电池参数 APN/电压/mAh/Wh）。

### 3. 生成七份手续
```
python scripts/gen_procedures.py
```
基于 `公共模板/`（空白版）原位编辑，输出 `出货手续包/{主单}/`：

### 4. 校验
- 文本层：机型齐全、无 AI 标注、运单号出现次数正确、品名行不超栏宽（安检单品名 x≤205、应急措施 x≤505、托书品名 y≤545 不压日期）。
- 注意：`get_text('dict')` 对中英 split span 会分行，且首行 y0 可能略超过滤边界，用 `get_text()` 拼接（去换行）或 words 级验证。

## 关键坑（实战踩过）

- **redact 矩形不得压进相邻文本区**：运单副本中文品名格底边是 662.9 表格横线，曾把 `CN_GOODS_RECT` 下界设成 720（越过条款格），`apply_redactions` 把右下角 "Shipper certifies..." 证明条款 x≥407.7 的文字全擦了（表现为条款中间缺词、句子断裂）。定位手段：模板 vs 生成件像素 diff 找差异带，再用 `get_text('dict')` 看该带内 span 被截断。改坐标前先查表格横线（`get_drawings` 长横线）确认格子真实边界；格内行多靠 `fit()` 缩字号，而不是扩大矩形。
- **补回被误删的模板文字要用真实基线**：`get_text('dict')` 的 bbox 是字形轮廓边界，与字体 metrics 基线不是一回事（同一 span 能差 1.4pt）；要用 `get_text('rawdict')` 的 char origin 拿内容流真实基线，并优先 `extract_font` 复用模板原字体。补写前必须先整体 redact 目标文本区，否则旧残片会和新文字叠影。
- **TextWriter 嵌入字体必须子集化再保存**：`TextWriter` + `Font('china-s')`/`Font(fontfile=simsun.ttc)` 会把整个字体文件（Droid Sans 3MB / SimSun 17MB）全量嵌入且不压缩（安检单 846KB→18MB、运单 28KB→3.5MB）。所有生成函数保存前一律 `doc.subset_fonts()` + `doc.save(out, garbage=3, deflate=True)`（子集后字体名带 `ABCDEF+` 前缀）；排查体积用 `xref_stream_raw` 找最大流，`Length1` 巨大即嵌入字体。
- **品名变体前缀判断必须去空白**：xlsx 出现过「5G 数字移动电话机 A3102」（5G 与数字间带空格），严格 `startswith('5G数字')` 会把明明存在的手机变体报成「没有变体行」。一律用 `bw.variant_cat(cn)`（去空白后判前缀）。
- **补充页服务用 ThreadingHTTPServer + `srv.timeout=0.5` 轮询退出**：单线程服务会被「只连不发请求」的代理/安全软件探测卡死（页面一直加载）；多线程下 `handle_request` 派线程即返回，不设超时则永远轮询不到 done 标志。页面同时落盘备份，浏览器被代理拦时直接开文件提交（JS 绝对地址 + CORS `*`）。
- **email 解析必须 `message_from_binary_file(open(path,'rb'))`**：文本模式中文变 `\uXXXX` 字面量。
- **中英混排必须分字体**：`china-s` 西文全宽(1em)，参考版西文半宽(0.5em)——按脚本切段，中文 `china-s` + 西文 `helv`，用 insert_text 返回宽度推进 x（`mixed_insert`）。
- **openpyxl 清空单元格**：`ws.cell(row,col,value=None)` 是"不赋值"不清空！必须 `.value=None` 属性赋值。
- **图片底 PDF（安检单/托书）无文本层**：表格线在 JPEG 里，坐标从同底图参考版（如 176-61334210）`get_text('dict')` 提取；底图 md5 一致则坐标通用。
- **docx sdt 控件**：公共模板占位符在 `w:sdtContent`，Word 显示控件框——替换文本后正则剥离整个 sdt 块为纯文本 run。
- **托运人声明文件名字段是不间断空格(U+00A0)**：glob/路径匹配用子串（如 `'托运人声明' in f`）。
- 条码/运单号保留原值时不重画（运单副本模板已有正确号码条码）。
- **PyMuPDF 1.28**：`insert_text` 返回 1 而非宽度，混排推进 x 用 `Font.text_length`；真实中文字体（SimSun）必须 `TextWriter`+`Font(fontfile=…)`，`insert_text(fontfile=…)` 丢 ToUnicode 提取变点。
